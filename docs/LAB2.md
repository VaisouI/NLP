# ЛР2: базовая модель и проверка входов

Проект продолжает ЛР1: тот же исходный SMS Spam Collection и SHA256,
тот же пользователь mluser и Ubuntu 24.04 VM. Отчёт ЛР1 — VM_REPORT.md.
Отчёт ЛР2 создаётся после реального запуска: LAB2_REPORT.md.

## Запуск на сохранённом стенде

Из корня существующего Codespace после получения кода ЛР2:

```bash
bash scripts/codespaces/run_lab2.sh
```

Сценарий возобновит сохранённую VM, передаст только исходный код, установит
зафиксированные зависимости в прежнее виртуальное окружение, выполнит Notebook,
pytest, Bandit и pip-audit от mluser. Затем labadmin установит root-эталон модели
и соберёт системные доказательства. Проверяются загрузка модели, обнаружение изменения
копии, включённая аутентификация Jupyter и реальный SSH-туннель на loopback.
Журналы и результаты автоматически возвращаются в Codespace.

Исходный диск VM, SSH-ключи и эталон датасета используются из ЛР1. Скрипт не создаёт
новую VM и не переустанавливает SSH/UFW. При остановке сохраняются диск и журнал
`.labvm/lab2-launcher.log`. Итог успеха — `LAB2_READY`.

## Модель и данные

- Исходный файл — 5574 англоязычных SMS; SHA256
  `7d039a24a6083ed9ef0f806ebad56bbb976e3aeb8de05669173bfdc4996c239d`.
- Строки, нарушающие политику входа, исключаются до разделения. У повторных
  нормализованных текстов сохраняется первое вхождение. Исходный файл не изменяется.
- Текущая фиксированная версия данных даёт 35 отклонённых строк с управляющими
  символами, 415 исключённых повторов и 5124 оставшихся записи.
- Разделение stratified 60/20/20, seed 42: train, фиксированный контроль CI,
  независимый test. После дедупликации группы не пересекаются.
- Статическая нормализация: NFKC, casefold, объединение пробельных символов.
  TF-IDF обучается только на train: 1–2-граммы, min_df=2, до 20000 признаков,
  sublinear_tf=True. LogisticRegression: C=1, class_weight=balanced,
  solver=liblinear, max_iter=1000, random_state=42.
- Параметры заданы заранее, подбор по тесту не выполняется. Веса классов изменяют
  функцию потерь; искусственного выравнивания числа сообщений нет.
- Основная метрика — F1 класса spam. Дополнительно: accuracy, precision/recall/F1
  по обоим классам, macro-F1, balanced accuracy и матрица ошибок.

Корпус старый и англоязычный; достаточность относится к учебному baseline.
Нет надёжных идентификаторов отправителя или времени, поэтому все связи источника
устранить нельзя. Результат не подтверждает переносимость на современные SMS.

## Команды внутри VM

```bash
source .venv/bin/activate
python -m src.cli train
python -m src.cli evaluate
python -m src.cli robustness
python -m src.cli validate
python -m pytest tests/ -q
python -m bandit -r src/
python -m pip_audit
printf '%s' '{"text":"Project lab2 meeting tomorrow at noon"}' | python -m src.cli predict
```

`train` обучает только при отсутствии артефакта и его baseline. При повторном
запуске существующая модель проверяется и используется; `evaluate` не обучает
новую модель. Несовместимые код, конфигурация, данные или baseline приводят к отказу.
Автоматического перезаписывания baseline результатами нового кандидата нет.

После клонирования опубликованного результата модели в Git не будет. Преподавателю
передаётся приватный архив lab2-results.zip: восстановите из него models/ в корень
проекта. При отсутствии исходного корпуса его получает
`python scripts/download_dataset.py` с проверкой SHA256. Затем установите
requirements.txt и выполните `evaluate`. Для нового обучения с другой конфигурацией
нужно отдельно пересмотреть версию артефакта и baseline; удалять эталон ради прохода
проверки не следует.

## Вход и ограничения

```json
{"text":"Project lab2 meeting tomorrow at noon"}
```

Ожидается ровно один объект с полем text строкового типа; дополнительные поля
отклоняются. Результат содержит prediction (ham/spam) и model_version (lab2-v1).
Вероятность не выдаётся. Неверная структура, тип, null, NaN/Inf, пустой текст,
невалидный Unicode и управляющие символы возвращают InputValidationError с кодом
и сообщением без исходного текста и traceback.

Пределы: 4096 кодовых точек Unicode и 16384 байта UTF-8 до и после нормализации.
Максимум корпуса — 910 кодовых точек; предел оставляет запас, ограничивая обработку
одного SMS. Вход не обрезается незаметно. Batch не поддерживается. Для тестов лимиты
снижены до 64/96 и создаются только небольшие входы. На каждом отклонении проверяется
нулевое число вызовов модели. CLI дополнительно ограничивает чтение JSON 65536 байтами.
Полный HTTP body limit до загрузки в память относится к ЛР4.

## Эксперимент

20 сообщений из независимого теста, по 10 каждого класса, выбираются фиксированным
seed. Проверяются регистр/пробелы и перестановка двух букв максимум в трёх словах.
Сравниваются метки, F1 и decision_function; decision score не называется
калиброванной вероятностью. Исходные тексты и преобразованные копии в Git не публикуются.
Нулевая доля смены метки на 20 примерах не доказывает устойчивость ко всем атакам.

Отдельно проверяется синтетическая строка только из эмодзи. Она допустима по форме,
но может не иметь признаков в словаре. Формальный OOD-критерий не реализован;
результат не объявляется доказательством работы OOD-детектора.

## Артефакты и защита

- `models/lab2-v1/model.skops` — TF-IDF, словарь, IDF и классификатор; файл вне Git.
- `security/model-manifest-lab2-v1.json` — SHA256, размер, версии и fingerprint.
- `/var/lib/ml-lab/model-integrity/lab2-v1.json` — root:root 0444, вне проекта.
- `metrics/baseline.json` — независимый test; `metrics/baseline_ci.json` — отдельный
  контроль для ЛР3. Значения кандидата не заменяют эти файлы автоматически.
- `metrics/training.json`, `lab2-data.json`, `validation-cases.json`,
  `error-analysis.json`, `robustness.json` — параметры и обезличенные результаты.
- `evidence/lab2/` — полные журналы, XML/JSON проверок и подтверждения защиты.

Перед загрузкой skops проверяется SHA256; неизвестные типы не разрешаются. Версия
scikit-learn должна совпадать. Данные и модель хранятся в приватных каталогах,
модель доступна mluser только для чтения. Root остаётся доверенной границей.
Skops снижает риск произвольной десериализации, но не доказывает корректность модели.

Jupyter остаётся на 127.0.0.1:8888 от mluser с аутентификацией. SSH-туннель
127.0.0.1:18888 → VM 127.0.0.1:8888 проверяется автоматически без публикации токена.
Для интерактивной работы можно создать такой же туннель из Codespace:

```bash
ssh -F "$PWD/.labvm/ssh_config" -N -L 127.0.0.1:18888:127.0.0.1:8888 ml-lab
```

Внешняя публикация порта для всех пользователей не требуется. Токен вводится только
в собственной сессии; в отчёт попадают факт включения аутентификации и HTTP-код отказа.
