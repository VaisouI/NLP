# Лабораторная работа № 1. Защищённое окружение NLP-проекта

Проект: классификация англоязычных SMS на обычные сообщения (`ham`) и спам (`spam`).
Подготовлены исходный код, Notebook, проверенные данные, фиксированные зависимости,
мини-модель угроз и сценарии настройки отдельной Ubuntu VM на Windows.

**Текущий статус:** анализ данных, аудит Python-зависимостей и проверка целостности
выполнены в контейнерной среде подготовки. Создание VM на Windows, настройка её SSH,
UFW, обновления ОС и работа от `mluser` требуют запуска на целевом компьютере.
Эти пункты пока не объявляются выполненными. Удалённый Git-репозиторий ещё не создан.

Для Windows начните с [пошаговой инструкции](docs/START_WINDOWS.md).
Для сдачи используйте [отчёт о выполненной части](docs/LAB1_REPORT.md),
[мини-модель угроз](security/THREAT_MODEL.md), Notebook и фактические результаты VM.
Файл `docs/VM_REPORT.md` появится только после сбора результатов на виртуальной машине.

Исходный формат — UTF-8, метка и текст разделены первой табуляцией. Каждая исходная
строка сохраняется: CSV-обработка кавычек не применяется. Исходные данные не балансировались
и не очищались от дубликатов. Подробные вычисления — в
[Notebook](notebooks/01_dataset_analysis.ipynb).

![Распределение классов](figures/class_distribution.png)

Дисбаланс может смещать модель к `ham`: постоянный прогноз этого класса даёт accuracy 86,60%
при нулевой полноте `spam`. Для последующих экспериментов нужны precision/recall/F1 класса
`spam`, macro-F1, balanced accuracy и матрица ошибок. При разбиении следует группировать
нормализованные одинаковые тексты, чтобы исключить попадание дубликатов в обучение и тест.

Корпус выбран для учебных экспериментов. Его возраст и язык ограничивают переносимость
результатов на современные сообщения и русскоязычные данные.

## Воспроизведение Python-части

Целевая среда: Ubuntu 24.04, Python 3.12, обычный пользователь. В каталоге проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install pip==26.2.2
python -m pip install -r requirements.txt
python -m pip check
python scripts/download_dataset.py
python scripts/check_integrity.py
python scripts/tamper_demo.py
python -m unittest discover -s tests -v
python -m ipykernel install --user --name ml-lab --display-name 'Python (ml-lab)'
python -m jupyter nbconvert --execute --to notebook --inplace \
  --ExecutePreprocessor.kernel_name=ml-lab \
  notebooks/01_dataset_analysis.ipynb
python -m pip_audit
```

Скачивание проверяет заранее сохранённый SHA256 архива до извлечения известных файлов.
Если существующий файл изменён, загрузчик завершится с ошибкой и не перезапишет его.
Эталон при обычной проверке не обновляется. Изменение версии датасета требует отдельного
осознанного пересмотра эталона, статистики и отчёта.

Зафиксировать фактически установленное окружение после разрешённых изменений:

```bash
python -m pip freeze > requirements.txt
python -m pip_audit --format=json --output pip-audit.json
```

Фиксация версий и `pip check` не заменяют аудит уязвимостей.
Отсутствие находок `pip-audit` относится к известным уязвимостям на момент запроса.

## SSH и Jupyter

Windows-сценарий создаёт Ed25519-ключ в профиле пользователя Windows и передаёт на VM
только публичную часть. В Git и отчёт приватный ключ не включается.
Он также сверяет ключ SSH-сервера через локальный канал управления Multipass,
проверяет новый вход по ключу до и после настройки UFW и отдельно проверяет отказ root.

Jupyter запускается обычным пользователем:

```bash
bash scripts/start_jupyter.sh
```

На Windows, в отдельном окне, для стандартного имени VM:

```powershell
ssh -F "$env:USERPROFILE\.ssh\config_ml-lab" -L 127.0.0.1:8888:127.0.0.1:8888 ml-lab
```

Откройте `http://127.0.0.1:8888` и используйте токен из текущего вывода Jupyter.
Не добавляйте токен в Git или отчёт. Внешнее правило UFW для 8888 не требуется.
VS Code устанавливается на Windows; расширение Remote SSH подключается к VM и
устанавливает удалённую часть IDE при первом подключении.

## Контроль целостности

Основной файл: `data/raw/SMSSpamCollection`.

```text
7d039a24a6083ed9ef0f806ebad56bbb976e3aeb8de05669173bfdc4996c239d
```

ZIP-архив:

```text
1587ea43e58e82b14ff1f5425c88e17f8496bfcdb67a583dbff9eefaf9963ce3
```

Проверка из корня проекта:

```bash
sha256sum data/raw/SMSSpamCollection
sha256sum --check security/SHA256SUMS
python scripts/check_integrity.py
```

Эталон в `security/` версионируется отдельно от игнорируемых данных. После развёртывания
сценарий администратора сохраняет дополнительный эталон в `/var/lib/ml-lab/integrity/`:
каталог `root:root 0755`, файлы `root:root 0444`. Обычный `mluser` может читать эталон,
но не изменять его. Проверка:

```bash
python scripts/check_integrity.py --require-protected-baseline
sha256sum --check /var/lib/ml-lab/integrity/SHA256SUMS
```

В среде подготовки защищённый системный эталон ещё не установлен. Сохранённые локальные
результаты относятся к эталону в репозитории. SHA256 обнаруживает изменение относительно
эталона, но не доказывает достоверность источника и правильность меток. Root способен
изменить и данные, и системный эталон.

## Секреты и Git

`.gitignore` исключает `.venv/`, кэши Python и Jupyter, `.env`, файлы ключей, сырые данные,
производные данные, модели и необработанные журналы целевой машины. Notebook, код,
проверенные агрегаты и эталонные хэши хранятся в Git.

`.env` может содержать пароли и API-ключи. При коммите эти значения попадают в историю,
клоны и резервные копии репозитория. `.gitignore` предотвращает обычное добавление
неотслеживаемого файла, но не удаляет уже сделанные коммиты. Для уже опубликованного
секрета требуются отзыв/ротация и отдельная очистка истории.

В приложенном каталоге инициализирован локальный Git-репозиторий с техническим
первоначальным коммитом. Датасет и `.venv` не отслеживаются. Публикация выполняется
после создания своего пустого удалённого репозитория:

```bash
git remote add origin URL_ВАШЕГО_ПУСТОГО_РЕПОЗИТОРИЯ
git push -u origin main
```

Перед коммитом результатов VM просмотрите `docs/VM_REPORT.md`; не добавляйте приватные
ключи, токены или необработанные журналы без проверки. Для сдачи предоставьте реальную
ссылку на созданный репозиторий и доступ преподавателю, если он приватный.
