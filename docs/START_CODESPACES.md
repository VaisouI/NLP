# Лабораторная в GitHub Codespaces

Точка запуска — терминал Codespaces, каталог `/workspaces/codespaces-blank` либо корень
своего репозитория. На Windows не устанавливаются пакеты или гипервизор.

Загрузите `lab1-codespaces.sh` в корень Codespace и выполните:

```bash
bash lab1-codespaces.sh
```

Сценарий проверяет KVM, создаёт отдельную Ubuntu 24.04 VM с 2 vCPU, 4 ГБ RAM и
виртуальным диском 30 ГБ, передаёт проект и выполняет лабораторные проверки.
При первом запуске отсутствующие QEMU и вспомогательные пакеты устанавливаются
автоматически внутри Codespace. Предварительные команды установки не требуются.
Основной файл отчёта после запуска — `docs/VM_REPORT.md`.

Файлы VM, seed с ключами и технические SSH-ключи находятся в `.labvm/` с правами 0700/0600
и исключены из Git. Исходный Ubuntu cloud image скачивается с cloud-images.ubuntu.com;
его SHA256 сверяется с опубликованным там SHA256SUMS и сохраняется в evidence/client/.
Проверка хэша не заменяет независимую проверку подписи издателя.

Клиент — Codespace. На нём создаётся клиентский Ed25519-ключ, а на гостевую VM передаётся
только его публичная часть. Дополнительно на этапе подготовки локального образа создаётся
отдельный серверный Ed25519-ключ для доверенной фиксации SSH host key; закрытая часть
передаётся только внутри приватного NoCloud seed в гостевую систему. Seed не входит в Git
или сдаваемый архив.

В гостевой системе labadmin выполняет администрирование, mluser — Python-часть без sudo.
SSH внутри VM использует порт 22; QEMU публикует его только на loopback Codespace:22222.
Все правила UFW относятся к гостевой VM. Firewall Codespaces не перенастраивается.

Для независимого доступа к консоли гостевой системы:

```bash
sudo python3 scripts/codespaces/console_vm.py "$PWD/.labvm/console.sock"
```

Выход из консоли — Ctrl+]. Для этой учебной VM настроен вход labadmin без пароля только
через её локальную serial-консоль. Доступ к сокету ограничен приватным каталогом Codespace.
Удалённый парольный вход SSH отключается и проверяется отдельно.

Обычный SSH от Codespace:

```bash
ssh -F "$PWD/.labvm/ssh_config" ml-lab
```

Административная SSH-сессия:

```bash
ssh -F "$PWD/.labvm/ssh_config" ml-lab-admin
```

После успешного выполнения:

- `docs/VM_REPORT.md` — результаты, версии, правила UFW, порты, SHA256 и таблица угроз.
- `notebooks/01_dataset_analysis.ipynb` — Notebook, выполненный внутри Ubuntu от mluser.
- `requirements.txt` — фактически установленные на VM Python-зависимости.
- `evidence/vm/` и `evidence/client/` — реальные журналы, исключённые из Git по умолчанию.
- `lab1-results.zip` — материалы для скачивания без VM и закрытых ключей.

При ошибке сценарий останавливается и выводит этап, который не завершён. VM и её диск
не удаляются автоматически: можно изучить журнал, открыть serial-консоль и повторить запуск.
Сценарий не объявляет все проверки пройденными при ошибке.

Для полного начала с нуля откройте https://github.com/codespaces, удалите нужный
Codespace через его меню `…` → `Delete`, затем создайте новый из шаблона `Blank`
(`Explore quick start templates` → `See all` → `Blank` → `Use this template`).
Удаление уничтожает файлы и VM внутри выбранного Codespace; опубликованный
GitHub-репозиторий при этом не удаляется. В новый Codespace загрузите актуальный
`lab1-codespaces.sh` и выполните ту же команду запуска.

Git-репозиторий подготовлен локально. Если исходный Blank Codespace ещё не связан с
вашим репозиторием, используйте Publish to GitHub в панели Source Control и выберите
собственный репозиторий. В отчёте укажите полученную фактическую ссылку. Временный адрес
Codespace не является ссылкой на Git-репозиторий.

Не удаляйте VM до сохранения результата и выполнения остальных лабораторных, использующих
тот же стенд. Для выключения без удаления диска:

```bash
ssh -F "$PWD/.labvm/ssh_config" ml-lab-admin 'sudo poweroff'
```

После сохранения и публикации материалов можно удалить весь Codespace через GitHub.
